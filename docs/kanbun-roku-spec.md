# kanbun-roku（渡世日月漢文録）仕様

最終更新: 2026-11-01
状態: 取り込みと区切り（座）まで実装済み。日記の生成は未実装（設計中）。

この文書は、これまでの会話で固まった内容をまとめたもの。リポジトリの実装そのものとは照合していないため、食い違いがあれば実装と `CLAUDE.md` を正とし、この文書を直す。

---

## 1. 目的

Claudeとの会話ログを、原本のままDBに保存する。そこへリンクした、漢文調のダイアリーを作る。後から見返すとき、日記から原本へ辿れる。後日の考察は注釈の層として積み重ねる。

## 2. 原則

1. 原本（`messages`）は追記のみ。更新・削除をしない。
2. ダイアリーは原本からの派生物。いつでも原本から作り直せる。
3. ダイアリーの各記述は、根拠となる原本の発言にリンクする。
4. 注釈（`annotations`）は後日の考察を足す層。原本には触れない。
5. このリポジトリは公開。実データはコミットしない。テストはダミーデータだけで書く。
6. 会話ログは機微な個人情報。外部に送信しない（LLMはローカルのOllama）。

| 項目 | 内容 |

## 4. データモデル

### 実装済み

| テーブル | 主な列と役割 |
|---|---|
| `messages` | `session_id`（会話のuuid）、`external_id`（発言のuuid）、`role`（user / assistant）、`body`（textブロックだけを連結）、`raw`（jsonb、発言全体）、`occurred_at`（UTC保存）、`source`（"claude_ai"）。`(source, external_id)` に一意制約。 |
| `segments` | 座。`session_id`、`first_message_id`、`last_message_id`、`segment_date`、`start_reason`、`end_reason`、`resumed`、`continued_from`。`(session_id, first_message_id)` に一意制約。 |
| `diary_entries` / `diary_links` / `annotations` | 当初の4テーブル構想の残り（ダイアリー、原本へのリンク、注釈）。 |

### 決定済み・未実装

- ダイアリーは座（segment）単位で1件にする。一意にするのは `segment_id`。`entry_date` は座の開始時刻（日本時間）から導出する。
- 区切りの規則を変えたときのために、規則の版（`rule_version`）を持つ方針。実装の有無は要確認。
- タグ：`tags` と、座・ダイアリーに結ぶ `taggings`（`source` 列で自動 / 手動を区別）。
- `diary_links` に「文の位置」の列を足すのは、文ごとのリンクに進むとき。

### 原本の保護

- モデル側で、保存済みの原本の更新と削除を拒否する。
- DB側のトリガーで、UPDATE / DELETE / TRUNCATE を拒否する。そのため、メインDBのスキーマは `db/structure.sql` で保存する。
- 開発用コマンド（`db:reset`、`db:truncate_all` など）は、development を保護環境に加えて止めてある。本当に作り直すときは、バックアップを取ってから `DISABLE_DATABASE_ENVIRONMENT_CHECK=1` を付ける。
- 例外的に原本を消す手順は `CLAUDE.md` に記載する。消した日のダイアリーは再生成する。機微情報の削除が目的なら、バックアップも消す。

## 5. 取り込み（実装済み）

- 入力：claude.ai のエクスポート `conversations.json`（約165MB。392会話、うち発言0件が7会話、発言は22,852件）。
- `body`：`content` のうち type が `text` のブロックだけを順につなげる。
- `raw`：発言全体を残す。thinking、tool_use、tool_result、injected_prompt_block、token_budget は `raw` にだけある。
- image と document のブロックは参照だけで、実体は入っていない。
- `role`：human を user にそろえる。assistant はそのまま。
- `session_id` は会話のuuid、`occurred_at` は発言の `created_at`。
- 本文が空の発言（2,105件）も、`body` を空にして取り込む。日記の素材からは除く。
- JSON内のNUL文字は置換する（jsonbに入らないため。実データでは0件）。
- 既定は dry-run。`APPLY=1` を付けたときだけ書く。全体を1トランザクションで書き、再実行しても重複しない（冪等）。
- 取り込みのあと、座の再計算（`rebuild!`）を呼ぶ。

### エクスポートの手順

- ブラウザ版かデスクトップ版の設定から行う（スマホアプリからは実行できない）。
- 届いたメールのリンクは24時間で期限切れ。目録（manifest）に、7つのファイルのリンクが入っている。
- 取り込みに要るのは `conversations` のzipだけ。`memories` などは落とさない。
- `data/incoming/` に置き、`data/export/` に展開する。`data/` はGit管理外。
- 目録と、取り込み後に不要になったzipは削除する。

## 6. 区切り（座）の規則（実装済み）

### 基本

- 区切りは、1つの会話の中で閉じる（会話をまたがない）。
- 境界の日時は、2026-10-30 日本時間 0:00（2026-10-29T15:00:00Z）。境界をまたぐ区切りは分けない。切り替えは発言ごとの時刻で行う。
- 境界より前：6時間以上の間隔があいたところで区切る（`gap`）。終了の合図も再開の合図も効かない。
- 境界以降：合図の規則を適用する。

### 終了の合図

- 対象は人間（user）の発言。40文字以下で、全体が一致したときだけ。空白・句点・感嘆符の差は無視する。
- 集合（`END_PHRASES`。定数で、足せる）：こちらからは以上です / 中断します / おやすみなさい / さようなら / いってきます
- 合図の発言と、直後から次のuser発言までのassistantの返答を、閉じる側の区切りに含める（`end_reason = end_phrase`）。
- assistantの発言は合図にならない。
- 合図のあとに「再開します」以外の発言が来たら、新しい区切りを始める（`start_reason = after_end`）。

### 再開の合図

- 人間の発言が「再開します」と全体一致したら、新しい区切りの最初の発言にする（`start_reason = resume_phrase`、`resumed = true`）。
- 直前の区切りが開いたままなら、暗黙に閉じる（`end_reason = implicit`）。
- 同じ会話の直前の区切りを `continued_from` で結ぶ。別の会話で「再開します」と言った場合は、`resumed = true` かつ `continued_from = NULL`。
- 過去分に「再開します」は全期間で1件。過去分には適用しない。

### 開いた区切り（open）

- 合図がなく、最後の発言から6時間未満なら `open`。
- 合図のuser発言で終わり、返答がなく6時間未満なら `open`（返答待ち）。返答が入れば閉じる。
- 最後の発言から6時間以上たっていれば、返答がなくても閉じる（合図なしは `gap`、合図ありは `end_phrase`）。取り込み時刻との比較。
- 閉じた区切りは更新しない（注釈やタグが結びつくため）。`open` の区切りだけ、次の取り込みで先頭の発言から計算し直す。
- 日記は `open` の区切りには作らない。

### 日付

- 区切りの日付は、開始時刻の日本時間の暦日。
- 0時をまたいで続いた分は、表示のときに24時・25時と出す（25時制）。
- 午前1時に「再開します」と言って始めた区切りは、翌日の記録になる。

## 7. ダイアリーの生成（未実装・設計中）

### 全体

- 1つの座から、1件のダイアリーを作る。
- 2段構成：1段目「曽良モード」（事実を簡潔に記録。原本へのリンク付き）→ 2段目「芭蕉モード」（紀行文として文章化。後回し）。
- 生成はSolid Queueのジョブで、1件ずつ流す。日付や座を指定して作り直せる。

### 曽良モードの出力形式

| 項目 | 内容 |
|---|---|
| 事実 | 何が行われたか。数字や固有名詞は原文と一致させる。 |
| 決定 | その座で決まったこと。 |
| 未解決 | 残った課題や保留。 |
| 考察 | 原文で語られたものに限る。由来（userかassistantか）を明示する。 |
| タグ | 3〜6個の名詞。 |

- リンクの粒度は、最初は座全体に1つ。モデルの出来を見てから、文ごとのリンクに進む。
- 文体は簡潔な漢字主体の記録体を目標にする。漢文の白文は下書きとして扱い、原文（現代語）と書き下し文を併記する。直した差分は注釈の層に残し、文体の見本として使う。見本には『奥の細道』（著作権切れ）を使える。

### 入力の前処理

- 素材は `body` の本文だけ。`thinking` やツールの出力は使わない。
- userの発言は全文。assistantの発言は先頭N文字（初期値600、定数）に切り詰め、コードブロックと長い引用は「（省略）」に置き換える。切り詰めた箇所には印を入れる。
- 1つの発言が単独で上限を超えるときは、先頭と末尾を残して、間を省略する。
- 上限を超える座は、発言の境界で塊に分け、塊ごとに曽良ノートを作って、最後に1つへ統合する。

### 文脈の見積もり

- モデル `qwen3-14b-16k`、`num_ctx = 16384` を明示する（入力が超えると黙って切り詰められることがあるため）。
- 思考（thinking）は切る（抽出の用途のため。切り方はOllamaのバージョンで要確認）。
- 文字数とトークン数の比（30件の測定）：最小1.27 / 下位10%で1.51 / 中央値1.70 / 75%で2.02 / 最大5.28。
- 本文だけで測った値。指示文は仮置き（指示文約1,000トークン＋出力約2,000トークン）。
- 1回で入る安全な上限は、約20,000文字。これを超える座は148件（約17.8%、全833件のうち）。
- 文字数ではなく、トークン数の見積もりで判定する。見積もりは `prompt_eval_count` の実測で較正する。

### モデル

- 呼び出しはRubyLLMの `RubyLLM.chat` を直接使う（`acts_as_chat` などのRails連携は使わない。既定のテーブルが、追記専用の `messages` と衝突するため）。
- 接続先は環境変数（`OLLAMA_API_BASE`）。コードには固定しない（公開リポジトリのため）。モデル名も環境変数（`DIARY_MODEL`、既定 `qwen3-14b-16k`）。
- 「メンタムさん」は、開発環境のローカルLLMの総称。メインは14b。
- 候補：`qwen3-14b-16k`、`qwen38-27b-q2k-waka`、`qwen3:30b-a3b`。短い座と長い座を1つずつ選び、同じ入力と指示で読み比べる。基準は、事実の正確さ、文体、所要時間。

### タグ

- 座とダイアリーに付ける。原本（`messages`）には付けない。
- 自動のタグは、ダイアリーを作り直すと入れ替わる。手動のタグは残る。
- 表記の揺れ（「連歌」と「れんが」など）は、正規化（辞書、全角半角の統一）で吸収する。新しいタグを「候補」として保留し、確認して採用する形も検討する。
- 検索：タグで一覧、複数タグの絞り込み、関連タグ。画面は、日記が作れてから。

## 8. 運用

### バックアップ（実装済み）

- `bin/backup-db`：`pg_dump` を gzip し、検証（`gzip -t`）してから配る。`.partial` で書いて、名前を直す。
- 保存先：外付けHDD（必須。書けなければERROR）と、外付けSSD（マウントされていれば）。それぞれ7世代を残す。
- NASには置かない（会話の全文を含むダンプを共有フォルダに置かないため）。
- launchd（LaunchAgent）で、毎日03:00。`ProgramArguments` は `["/bin/bash", "<スクリプトのパス>"]` の形にする。スクリプトを直接起動すると、外付けへの書き込みが `Operation not permitted` になった（理由は未調査）。
- `/bin/bash` にフルディスクアクセスが必要。
- スクリプトは内蔵ディスクに置いて、リポジトリ側の原本からコピーする。`plist` やスクリプトを変えたら、再コピーして再登録する。
- ログ：`log/backup.log`。復元は別名DBに戻して件数を確認する手順を確認済み。
- 手動で取るときは `launchctl kickstart -k gui/$(id -u)/com.kanbun-roku.backup`。

### Git

- 公開リポジトリ。コミットのメールアドレスは、このリポジトリだけ、GitHubのnoreplyアドレス。
- コミット前に、パスやホスト名の混入を `git grep --cached` で確認する。
- `data/`、`log/`、バックアップ（`*.sql.gz`）、`master.key`、`vendor/bundle` はGit管理外。
